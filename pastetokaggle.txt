"""
Universal Product Categorizer — v4  (Barcode-first direct match, then Embedding+LLM cascade)
=================================================================================================
★★★ DUAL-GPU PATCH ★★★  (carried over from v3)
  Original bug: OLLAMA_URL / OLLAMA_EMBED_URL were hardcoded to port 11434 (GPU 0 only).
  Two Ollama servers were started (11434 + 11435) but every single embedding / LLM / verifier
  call always went to 11434 — GPU 1 sat idle the whole run (0% util, 0 MiB used).

  Fix applied here:
    1. A round-robin host picker (`next_ollama_host()`) hands out 127.0.0.1:11434 / :11435
       alternately (thread-safe) to every outgoing request — embedding, LLM adjudication,
       AND verifier calls all rotate across whatever GPUs are actually running.
    2. Works with 1 GPU or 2 GPUs automatically — with 1 GPU the cycle just returns the same
       host every time (no behavior change, no risk).
    3. LLM_BATCH_WORKERS / VERIFIER_BATCH_WORKERS / EMBED_MAX_WORKERS are now scaled by the
       *actually detected* GPU count (2x per extra GPU) so the round-robin has enough
       concurrent batches in flight to actually keep both GPUs busy.
    4. Server startup now logs stdout/stderr to files (instead of discarding them) and prints
       the tail of the relevant log if a server fails to come up in time — makes future
       startup failures debuggable instead of a bare "did not start in time".

★★★ REFERENCE-CORPUS SOURCE FILTER ★★★  (carried over from v3)
  Previously ref_df (the reference/training corpus used for kNN + LLM candidates) was built
  from EVERY row in the workbook that simply had a non-blank lulu_category — regardless of
  which customer that row came from.
  Fix: ref_df now ALSO requires source_customer to be "LULU" or "GRANDMALL" (case/whitespace
  insensitive). Rows from any other source_customer are excluded from the reference corpus,
  even if they happen to have a lulu_category filled in. Everything downstream (barcode index,
  embeddings, kNN, LLM candidates) is unchanged in logic — it just now runs over this
  narrower, cleaner reference set. The sheet used is unchanged (LULU_SHEET = "data").

★★★ THINKING-MODE FIX (this edit) ★★★
  Symptom: Stage 3 (and eventually Stage 4) logged repeated
      raw content (first 600 chars): ''
  on BOTH GPU hosts, surviving retries, for a subset of batches.

  Root cause: qwen3:14b and gpt-oss:20b are both "thinking" models. Ollama auto-enables
  thinking whenever a chat request omits the top-level `think` field — neither call_ollama()
  nor call_verifier() ever set it. A thinking model's reasoning trace is returned in a
  SEPARATE message["thinking"] field; message["content"] only gets the JSON answer AFTER the
  model finishes reasoning. OLLAMA_NUM_PREDICT (700) caps thinking + answer tokens COMBINED.
  On batches where the model reasoned longer (harder/more ambiguous items — the system prompt
  explicitly invites this via the misleading-token warnings), it used the entire 700-token
  budget still inside <think> and never emitted an answer -> content == "". This is a
  token-budget effect, not a network/GPU problem, which is why it showed up on both hosts and
  survived retries.

  Fix:
    1. qwen3 (Stage 3) — thinking has a real off-switch. We now pass "think": False at the
       TOP LEVEL of the request payload (a sibling of "model"/"messages", NOT inside
       "options" — a common mistake). No hidden reasoning tokens, full num_predict budget
       goes to the actual JSON answer.
    2. gpt-oss (Stage 4 verifier) — thinking CANNOT be disabled for this model; passing
       True/False is silently ignored. Only "low" / "medium" / "high" is honored. We pass
       "think": "low" to minimize (not eliminate) the trace, and size a SEPARATE, larger
       num_predict budget (OLLAMA_NUM_PREDICT_VERIFIER) for verifier calls so the trace still
       has room to finish before the answer.
    3. Debug logging now also surfaces message["thinking"] (length + tail) whenever a batch's
       parsed response length doesn't match the input, so any future truncation is obvious
       at a glance instead of a bare empty string.
  Nothing about the matching/categorization logic, prompts, or thresholds was changed.

★★★ OLLAMA CRASH RECOVERY (this edit) ★★★
  Symptom: partway through Stage 3, EVERY batch on a given host started failing with
      Failed to establish a new connection: [Errno 111] Connection refused
  on that host, for hundreds of consecutive batches, never recovering — forcing a manual
  KeyboardInterrupt and a full notebook restart (twice, per the logs).

  Root cause: "Connection refused" (vs. a timeout or a 5xx) means the `ollama serve` PROCESS
  itself died on that GPU instance, not that a single request failed. Most likely trigger on a
  16GB T4: OLLAMA_MAX_LOADED_MODELS=2 + OLLAMA_KEEP_ALIVE=60m meant the Stage-2 embedding model
  (qwen3-embedding:4b, ~2.5GB) was still resident when Stage 3 loaded qwen3:14b (~9.3GB weights)
  on the SAME GPU instance, on top of KV-cache for OLLAMA_NUM_PARALLEL=2 concurrent slots at
  num_ctx=8192 — tight enough on 16GB to OOM-kill the ollama process under sustained load. Once
  the process is dead, next_ollama_host() keeps round-robining requests to a corpse: every
  attempt (and every retry) fails identically, forever, because nothing ever restarts it.

  Fix (defense in depth — both layers matter):
    1. PREVENT: OLLAMA_MAX_LOADED_MODELS dropped from "2" to "1" (CELL 0). This forces Ollama to
       evict the previous stage's model before loading the next one on a given GPU instance, so
       two large models are never resident on the same 16GB card at once. Costs a one-time
       reload delay (~10-30s) at the start of each stage, which is negligible against total
       runtime.
    2. RECOVER: CELL 1's startup logic is refactored into a reusable `_start_ollama_instance()`
       function (was inline, couldn't be called again). A new `ensure_host_alive()` (CELL 1B)
       is called right before every embedding/LLM/verifier request; if the target host is down,
       it relaunches `ollama serve` pinned to the correct GPU with the correct env vars and waits
       for it to come back, instead of firing a doomed request. This is thread-safe with a
       cooldown so concurrent workers hitting the same dead host don't each try to restart it.
    3. Restart attempts are counted (`_host_restart_count`) and reported in the final Summary
       sheet, so a run that self-healed is visible after the fact rather than looking identical
       to one that never had a problem.
  Nothing about the matching/categorization/thinking-mode logic was changed.

★★★ THINK-LEAK FIX + SPEED (this edit) ★★★
  Symptom: even with think=False set and confirmed in the Stage 3 header log line
      Stage 3 — sending 9,280 row(s) to Ollama (qwen3:14b, think=False) …
  a chunk of batches STILL came back with raw content == '' — and the whole stage's ETA was
  ~28,300s (7.9 hours) for one file, way slower than a 14B model producing a few hundred tokens
  of JSON per batch should take.

  Root cause: Ollama's top-level "think": false is documented to work for the plain qwen3:8b
  tag, but there is a long, still-active pattern of open ollama/ollama GitHub issues where it is
  silently ignored for OTHER qwen3 tags/quantizations/versions (e.g. #12234 qwen3:4b, #12610
  qwen3:30b, #12906/#13353/#14798 qwen3-vl variants) — the model keeps "thinking" regardless,
  burning the entire num_predict budget on the hidden trace every time. This is NOT a transient
  network glitch, so the existing retry loop calling the identical request 3x just reproduced
  the identical empty result 3x — this alone explains most of the slowness (generating a full
  reasoning trace up to the token budget is much slower than a short JSON answer, and doing it
  3 times per affected batch multiplies that cost).

  Fix:
    1. Belt-and-suspenders suppression: qwen3's OWN chat template honors literal "/no_think" in
       the prompt text, independent of Ollama's API-level "think" field — this is a SEPARATE
       code path in Ollama's model renderer, so it can still work even when the API-level
       wiring for a given tag is one of the buggy ones. Appended to the Stage-3 user message
       whenever LLM_THINK is False.
    2. OLLAMA_NUM_PREDICT raised 700 → 1200 as a safety margin in case suppression is still only
       partial for a given call.
    3. New `ThinkingLeakError` + thread-safe `_thinking_leak_total` counter: call_ollama() now
       raises this distinct exception when the true leak signature shows up (content empty AND
       thinking substantial AND nothing parseable to salvage) — a genuine partial answer is
       still returned normally rather than treated as a leak, so the existing last-attempt
       salvage behavior is untouched. `_process_llm_batch()` catches it specifically and gives
       up after 2 hits instead of burning the full LLM_MAX_RETRIES budget on a failure retries
       cannot fix. The total leak count is printed after Stage 3 and added to the Summary sheet,
       so you can see directly whether this actually got the model to stop thinking (near 0 =
       fixed) or whether qwen3:14b's specific build genuinely can't be suppressed this way (large
       count persists = worth trying LLM_MODEL="qwen3:8b" instead, which is the tag most
       consistently reported to honor think=False).
  Nothing about the matching/categorization/crash-recovery logic was changed.
=================================================================================================

# %% CELL 1B — ★ ROUND-ROBIN HOST PICKER + GPU-SCALED CONCURRENCY ★
# ============================================================================
# This is the actual dual-GPU fix. Every outgoing embedding / LLM / verifier
# request calls next_ollama_host() to get a host, instead of using one
# hardcoded URL. With 2 GPUs running, consecutive requests alternate
# 11434 -> 11435 -> 11434 -> ... so both GPUs get simultaneous work whether
# you're in the embedding stage, the LLM stage, or the verifier stage.
import itertools, threading

_host_cycle = itertools.cycle(OLLAMA_HOSTS)
_host_lock  = threading.Lock()

def next_ollama_host() -> str:
    with _host_lock:
        return next(_host_cycle)

# ★ CRASH-RECOVERY FIX: called right before every embedding/LLM/verifier request. If the
# target Ollama instance has died (e.g. OOM-killed under load — see module docstring),
# relaunch it pinned to the correct GPU and wait for it to come back, instead of firing a
# request at a dead process. Thread-safe with a per-host cooldown so multiple worker threads
# that discover the same dead host at once don't each try to restart it in parallel.
_restart_lock          = threading.Lock()
_last_restart_attempt  = {}   # host -> unix time of last restart attempt
_host_restart_count     = 0    # total successful restarts this run, reported in the Summary sheet

def ensure_host_alive(host: str, restart_timeout_s: int = 90, cooldown_s: int = 20) -> bool:
    global _host_restart_count
    if _ollama_running(host):
        return True
    with _restart_lock:
        if _ollama_running(host):          # re-check inside the lock — another thread may have just fixed it
            return True
        now = time.time()
        last = _last_restart_attempt.get(host, 0)
        if now - last < cooldown_s:
            # A restart was just attempted (by this thread or another) — don't pile on.
            # Release the lock implicitly by falling through to the sleep below isn't needed;
            # just wait out the remaining cooldown and re-check.
            wait_s = cooldown_s - (now - last)
        else:
            wait_s = 0
        _last_restart_attempt[host] = now
        gpu_id = GPU_ID_FOR_HOST[host]
        port   = PORT_FOR_HOST[host]
        print(f"  ⚠ {host} (GPU {gpu_id}) is not responding — attempting to restart Ollama …")
        if wait_s > 0:
            time.sleep(wait_s)
            if _ollama_running(host):
                return True
        log_path = _start_ollama_instance(gpu_id, port, host, restart=True)
        ok = _wait_for_ollama(host, timeout_s=restart_timeout_s)
        if ok:
            _host_restart_count += 1
            print(f"  ✓ {host} (GPU {gpu_id}) restarted successfully "
                  f"(restart #{_host_restart_count} this run)")
        else:
            tail = ""
            if os.path.exists(log_path):
                with open(log_path) as f:
                    tail = f.read()[-1500:]
            print(f"  ✗ {host} (GPU {gpu_id}) failed to come back within {restart_timeout_s}s. "
                  f"Log tail:\n{tail}")
        return ok

# Scale concurrency to however many GPUs we actually got. With 1 GPU this is
# identical to the original tuned values (2 / 2 / 6). With 2 GPUs it doubles,
# so there are enough batches in flight for the round-robin to actually keep
# both GPUs busy instead of just alternating idle time.
LLM_BATCH_WORKERS       = _LLM_BATCH_WORKERS_PER_GPU * _GPU_COUNT
VERIFIER_BATCH_WORKERS  = _VERIFIER_BATCH_WORKERS_PER_GPU * _GPU_COUNT
EMBED_MAX_WORKERS       = _EMBED_MAX_WORKERS_PER_GPU * _GPU_COUNT
print(f"  Concurrency scaled for {_GPU_COUNT} GPU(s): "
      f"LLM_BATCH_WORKERS={LLM_BATCH_WORKERS}, "
      f"VERIFIER_BATCH_WORKERS={VERIFIER_BATCH_WORKERS}, "
      f"EMBED_MAX_WORKERS={EMBED_MAX_WORKERS}")
print(f"  Thinking mode: qwen3 think={LLM_THINK} | gpt-oss think_level={VERIFIER_THINK_LEVEL!r} "
      f"(gpt-oss cannot fully disable thinking)")

def normalize_barcode(val):
    if val is None or (isinstance(val, float) and pd.isna(val)):
        return None
    if isinstance(val, float):
        val = f"{val:.0f}"
    s = str(val).strip()
    if s == "" or s.lower() in ("nan", "none", "0", "0.0"):
        return None
    if "e" in s.lower():
        try:
            s = f"{float(s):.0f}"
        except ValueError:
            pass
    if s.endswith(".0"):
        s = s[:-2]
    s = re.sub(r"\D", "", s)
    if not s or set(s) == {"0"} or len(s) < 6:
        return None
    return s

def guess_brand_rule(name: str):
    toks = re.findall(r"[A-Z0-9']+", str(name).upper())
    for n in (3, 2, 1):
        if len(toks) >= n:
            cand = " ".join(toks[:n])
            if cand in BRAND_SET:
                return cand, "rule_exact", 100.0
    cand = " ".join(toks[:2]) if len(toks) >= 2 else (toks[0] if toks else "")
    if len(cand) < 5:
        return None, "rule_none", 0.0
    match = process.extractOne(cand, FUZZY_BRAND_POOL, scorer=fuzz.token_sort_ratio,
                                score_cutoff=BRAND_FUZZY_CUTOFF)
    if match:
        return match[0], "rule_fuzzy", float(match[1])
    return None, "rule_none", 0.0

def _hash_list(items) -> str:
    h = hashlib.sha256()
    for it in items:
        h.update(str(it).encode("utf-8", errors="ignore")); h.update(b"\x00")
    return h.hexdigest()[:20]

def _ollama_embed_chunk(chunk: list, model: str) -> list:
    payload = {"model": model, "input": chunk}
    last_err = None
    for attempt in range(3):
        host = next_ollama_host()            # ★ round-robin: alternates GPU 0 / GPU 1
        if not ensure_host_alive(host):      # ★ CRASH-RECOVERY FIX
            last_err = f"{host}: down and could not be restarted"; time.sleep(1 * (attempt + 1)); continue
        embed_url = f"{host}{OLLAMA_EMBED_PATH}"
        try:
            resp = requests.post(embed_url, json=payload, timeout=120)
            resp.raise_for_status()
            embs = resp.json().get("embeddings")
            if not embs or len(embs) != len(chunk):
                raise ValueError("unexpected /api/embed response shape")
            return embs
        except Exception as e:
            last_err = f"{host}: {e}"; time.sleep(1 * (attempt + 1))
    raise RuntimeError(f"Ollama embedding failed: {last_err}")

def ollama_embed_texts(texts: list, model: str, batch_size: int = EMBED_BATCH_SIZE,
                        max_workers: int = None, label: str = "") -> np.ndarray:
    if max_workers is None:
        max_workers = EMBED_MAX_WORKERS   # ★ resolved at call time, already GPU-scaled
    if not texts:
        return np.zeros((0, 0), dtype=np.float32)
    n_chunks = (len(texts) + batch_size - 1) // batch_size
    chunks = [texts[i*batch_size:(i+1)*batch_size] for i in range(n_chunks)]
    results = [None] * n_chunks
    t0 = time.time()
    with concurrent.futures.ThreadPoolExecutor(max_workers=max_workers) as ex:
        futs = {ex.submit(_ollama_embed_chunk, c, model): i for i, c in enumerate(chunks)}
        done = 0
        for fut in concurrent.futures.as_completed(futs):
            results[futs[fut]] = fut.result()
            done += 1
            elapsed = time.time() - t0
            eta = (elapsed / done) * (n_chunks - done)
            if done % 5 == 0 or done == n_chunks:
                print(f"  [{label}] embedding chunk {done}/{n_chunks}  "
                      f"({elapsed:.1f}s elapsed, ~{eta:.1f}s left)")
    flat = [v for chunk in results for v in chunk]
    arr = np.array(flat, dtype=np.float32)
    norms = np.linalg.norm(arr, axis=1, keepdims=True); norms[norms == 0] = 1.0
    return arr / norms

def get_cached_embeddings(texts: list, model: str, label: str) -> np.ndarray:
    if not texts:
        return np.zeros((0, 0), dtype=np.float32)
    key = _hash_list(texts) + "_" + model.replace(":", "_").replace("/", "_")
    path = os.path.join(CACHE_DIR, f"emb_{label}_{key}.npy")
    if os.path.exists(path):
        try:
            arr = np.load(path)
            if arr.shape[0] == len(texts):
                print(f"  ✓ [{label}] embedding cache hit → {path}")
                return arr
        except Exception:
            pass
    print(f"  Encoding {len(texts):,} texts via Ollama (model={model}) …")
    arr = ollama_embed_texts(texts, model=model, label=label)
    try:
        np.save(path, arr)
    except Exception as e:
        print(f"  ⚠ could not cache embeddings: {e}")
    return arr

# ★ THINK-LEAK FIX (this edit): Ollama's top-level "think" field is documented to work for the
# plain qwen3:8b tag but is inconsistently honored for OTHER qwen3 tags/quantizations across
# Ollama versions — this is a real, still-open pattern across many ollama/ollama GitHub issues
# (#12234, #12610, #12906, #13353, #14798, and others): "think": false is silently ignored and
# the model burns its ENTIRE num_predict budget on the hidden <think> trace, producing
# message["content"] == "" every single time for that prompt — NOT a transient glitch, so
# retrying the identical request 3x just wastes 3x the time for the same empty result. This
# class + counter let call_ollama() signal that specific failure mode distinctly so
# _process_llm_batch() can stop retrying early instead of burning the full retry budget.
class ThinkingLeakError(RuntimeError):
    """Raised when a thinking-capable model ignored think=False/no_think and produced an empty
    answer because the entire token budget went to the hidden reasoning trace instead."""
    pass

_thinking_leak_lock  = threading.Lock()
_thinking_leak_total = 0

def _record_thinking_leak():
    global _thinking_leak_total
    with _thinking_leak_lock:
        _thinking_leak_total += 1

def call_ollama(items: list, debug_label: str = ""):
    host = next_ollama_host()            # ★ round-robin: alternates GPU 0 / GPU 1
    if not ensure_host_alive(host):      # ★ CRASH-RECOVERY FIX: restart it here rather than
        raise RuntimeError(f"Ollama host {host} is down and could not be restarted")  # firing a doomed request
    chat_url = f"{host}{OLLAMA_CHAT_PATH}"
    user_msg = "Classify these products:\n" + json.dumps({"items": items}, ensure_ascii=False)
    if not LLM_THINK:
        # ★ THINK-LEAK FIX: belt-and-suspenders. Qwen3's OWN chat template honors "/no_think"
        # in the prompt text independently of Ollama's API-level "think" field, so send both —
        # if Ollama's wiring for this particular tag/quant is one of the buggy ones, the
        # template-level instruction is a separate code path that can still catch it.
        user_msg += "\n\n/no_think"
    payload = {
        "model": LLM_MODEL,
        "messages": [
            {"role": "system", "content": SYSTEM_PROMPT},
            {"role": "user", "content": user_msg},
        ],
        "format": "json",
        # ★ THINKING-MODE FIX: top-level field, NOT inside "options". qwen3 defaults to
        #   thinking=on when this is omitted, which was silently burning the whole
        #   num_predict budget on hidden reasoning tokens (message["thinking"]) before the
        #   model ever got to the JSON answer on harder batches -> empty content.
        "think": LLM_THINK,
        "stream": False,
        "options": {"temperature": 0.1, "num_predict": OLLAMA_NUM_PREDICT, "num_ctx": OLLAMA_NUM_CTX},
    }
    resp = requests.post(chat_url, json=payload, timeout=LLM_REQUEST_TIMEOUT)
    resp.raise_for_status()
    message = resp.json()["message"]
    content = message.get("content", "")  # .get(), not [..] — content can legitimately be absent/empty
    try:
        parsed = json.loads(content)
    except json.JSONDecodeError:
        matches = re.findall(r"\{[^{}]*\}", content)
        parsed = []
        for m in matches:
            try:
                obj = json.loads(m)
                if "category" in obj or "brand" in obj:
                    parsed.append(obj)
            except json.JSONDecodeError:
                break
    if isinstance(parsed, dict):
        if "items" in parsed and isinstance(parsed["items"], list):
            parsed = parsed["items"]
        else:
            for v in parsed.values():
                if isinstance(v, list):
                    parsed = v; break
            else:
                parsed = [parsed] if parsed else []
    if not isinstance(parsed, list):
        raise ValueError("Model did not return a JSON array")
    if len(parsed) != len(items):
        print(f"  [debug {debug_label} host={host}] raw content (first 600 chars): {content[:600]!r}")
        thinking = message.get("thinking") or ""
        if thinking:
            # ★ THINK-LEAK FIX: this is the tell. If content is empty/short but thinking is
            #   long, the model spent its whole num_predict budget reasoning and never got to
            #   answer. Only escalate to ThinkingLeakError when parsed is EMPTY (nothing to
            #   salvage) — if the model returned SOME items despite the mismatch, keep the old
            #   behavior of returning that partial list so the existing last-attempt salvage
            #   logic in _process_llm_batch still gets a chance to use it.
            print(f"  [debug {debug_label} host={host}] thinking field had {len(thinking)} chars "
                  f"(num_predict={OLLAMA_NUM_PREDICT}, think={LLM_THINK}) — model may have run out "
                  f"of budget before answering. Tail: {thinking[-300:]!r}")
            if not parsed and len(thinking) > 200:
                _record_thinking_leak()
                raise ThinkingLeakError(
                    f"host={host} debug_label={debug_label}: {len(thinking)} chars of thinking, "
                    f"0 answer items — think=False/no_think did not suppress reasoning for this "
                    f"model tag (known Ollama issue for some qwen3 variants)")
    return parsed

def _process_llm_batch(batch_rows_idx, batch_df):
    """Runs one Stage-3 batch end to end (with retries). Safe to call from multiple threads."""
    items = build_batch_payload(batch_df)
    result = None
    thinking_leak_hits = 0
    for attempt in range(1, LLM_MAX_RETRIES + 1):
        try:
            candidate = call_ollama(items, debug_label=f"{batch_rows_idx[0]} attempt {attempt}")
            if len(candidate) == len(items):
                result = candidate; break
            if attempt == LLM_MAX_RETRIES and candidate:
                result = candidate
        except ThinkingLeakError as e:
            # ★ THINK-LEAK FIX: this is a deterministic template/model behavior, not a network
            # blip — identical retries almost always reproduce the identical empty result. Give
            # it one extra try in case temperature=0.1 randomness saves it, but don't burn the
            # full LLM_MAX_RETRIES budget chasing a failure mode retries can't fix.
            thinking_leak_hits += 1
            print(f"  ⚠ batch starting {batch_rows_idx[0]} attempt {attempt}: {e}")
            if thinking_leak_hits >= 2:
                print(f"  ✗ batch starting {batch_rows_idx[0]}: giving up early after "
                      f"{thinking_leak_hits} thinking-leak hits (retrying further would just "
                      f"repeat the same result) — marking UNKNOWN")
                break
        except Exception as e:
            print(f"  ⚠ batch starting {batch_rows_idx[0]} attempt {attempt} failed: {e}")
        if attempt < LLM_MAX_RETRIES:
            time.sleep(2)

    out = {}
    if not result:
        for ridx in batch_rows_idx:
            out[ridx] = {"category": "UNKNOWN", "confidence": 0.0, "reason": "no LLM response"}
        return out

    if len(result) < len(batch_rows_idx):
        result = result + [{}] * (len(batch_rows_idx) - len(result))
    for ridx, o in zip(batch_rows_idx, result):
        out[ridx] = o
    return out

            if brand_guess and brand_guess.lower() not in ("none", "nan", "unknown"):

        done_batches += 1
        if done_batches % 10 == 0 or done_batches == len(batches):
            elapsed = time.time() - t0
            eta = (elapsed / done_batches) * (len(batches) - done_batches)
            print(f"  … {done_batches}/{len(batches)} batches done "
                  f"({elapsed:.0f}s elapsed, ~{eta:.0f}s left)")

VERIFIER_SYSTEM_PROMPT = (
    "You are a strict QA reviewer for a product-categorization system. You will be "
    "shown a product, the category it was assigned, and a reference example product "
    "that already belongs to that category. Decide if the assignment is CORRECT, or "
    "AMBIGUOUS/WRONG. Judge by true semantic meaning, not superficial word overlap — "
    "the same misleading-token traps apply (e.g. a flavored spice mix named after an "
    "ingredient is not that raw ingredient; a diet/zero soft drink is still a "
    "beverage, not a health product). If the product could plausibly belong to more "
    "than one very different category, or the assigned category is a poor semantic "
    "fit, mark it ambiguous/wrong rather than rubber-stamping it.\n\n"
    "Respond with ONLY a single JSON OBJECT (no prose, no markdown fences):\n"
    '{"items": [{"verified": true/false, "ambiguous": true/false, '
    '"confidence": 0.0, "note": "<=15 words"}, ...]}\n'
    "One object per input item, SAME ORDER as given."
)

def build_verifier_payload(rows: pd.DataFrame):
    items = []
    for _, r in rows.iterrows():
        assigned_cat = r["lulu_category_final"]
        ex = r["_cand_examples"].get(assigned_cat) if isinstance(r.get("_cand_examples"), dict) else None
        items.append({
            "name": r["material_name"],
            "assigned_category": assigned_cat,
            "reference_example": ex,
            "hints": build_hint_block_for_llm(r),
        })
    return items

def call_verifier(items: list, debug_label: str = ""):
    host = next_ollama_host()            # ★ round-robin: alternates GPU 0 / GPU 1
    if not ensure_host_alive(host):      # ★ CRASH-RECOVERY FIX: restart it here rather than
        raise RuntimeError(f"Ollama host {host} is down and could not be restarted")  # firing a doomed request
    chat_url = f"{host}{OLLAMA_CHAT_PATH}"
    user_msg = "Review these category assignments:\n" + json.dumps({"items": items}, ensure_ascii=False)
    payload = {
        "model": VERIFIER_MODEL,
        "messages": [
            {"role": "system", "content": VERIFIER_SYSTEM_PROMPT},
            {"role": "user", "content": user_msg},
        ],
        "format": "json",
        # ★ THINKING-MODE FIX: gpt-oss CANNOT disable thinking — passing True/False is
        #   silently ignored for this model, only "low"/"medium"/"high" is honored. We ask
        #   for the shortest trace and size num_predict (below) with extra headroom for it.
        "think": VERIFIER_THINK_LEVEL,
        "stream": False,
        "options": {"temperature": 0.0, "num_predict": OLLAMA_NUM_PREDICT_VERIFIER, "num_ctx": OLLAMA_NUM_CTX},
    }
    resp = requests.post(chat_url, json=payload, timeout=LLM_REQUEST_TIMEOUT)
    resp.raise_for_status()
    message = resp.json()["message"]
    content = message.get("content", "")
    try:
        parsed = json.loads(content)
    except json.JSONDecodeError:
        matches = re.findall(r"\{[^{}]*\}", content)
        parsed = []
        for m in matches:
            try:
                obj = json.loads(m)
                if "verified" in obj:
                    parsed.append(obj)
            except json.JSONDecodeError:
                break
    if isinstance(parsed, dict):
        parsed = parsed.get("items", [parsed] if parsed else [])
    if not isinstance(parsed, list):
        raise ValueError("Verifier did not return a JSON array")
    if len(parsed) != len(items):
        print(f"  [verifier debug {debug_label} host={host}] raw (first 500 chars): {content[:500]!r}")
        thinking = message.get("thinking") or ""
        if thinking:
            print(f"  [verifier debug {debug_label} host={host}] thinking field had {len(thinking)} "
                  f"chars (num_predict={OLLAMA_NUM_PREDICT_VERIFIER}, think={VERIFIER_THINK_LEVEL!r}) "
                  f"— gpt-oss may still be running long on its trace. Tail: {thinking[-300:]!r}")
    return parsed

def _process_verifier_batch(batch_rows_idx, batch_df):
    items = build_verifier_payload(batch_df)
    result = None
    for attempt in range(1, LLM_MAX_RETRIES + 1):
        try:
            candidate = call_verifier(items, debug_label=f"{batch_rows_idx[0]} attempt {attempt}")
            if len(candidate) == len(items):
                result = candidate; break
        except Exception as e:
            print(f"  ⚠ verifier batch starting {batch_rows_idx[0]} attempt {attempt} failed: {e}")
        time.sleep(2)

    out = {}
    if not result:
        for ridx in batch_rows_idx:
            out[ridx] = None  # signal: leave original verdict untouched
        return out
    if len(result) < len(batch_rows_idx):
        result = result + [{}] * (len(batch_rows_idx) - len(result))
    for ridx, o in zip(batch_rows_idx, result):
        out[ridx] = o
    return out

work_df["verified"]        = None
work_df["verifier_ambiguous"] = None
work_df["verifier_note"]      = ""
work_df["verifier_model"]     = ""

if RUN_VERIFIER_STAGE and len(work_df):
    verify_mask = (work_df["category_method"] == "llm") & (work_df["lulu_category_final"] != "UNKNOWN")
    if VERIFY_BORDERLINE_KNN:
        borderline = (work_df["category_method"] == "embed_knn_auto") & \
                     (work_df["category_conf"] < AUTO_ACCEPT_MIN_SIM + VERIFY_KNN_MARGIN)
        verify_mask = verify_mask | borderline

    verify_idx = work_df.index[verify_mask].tolist()
    print(f"Stage 4 — sending {len(verify_idx):,} assignment(s) to verifier "
          f"({VERIFIER_MODEL}, think={VERIFIER_THINK_LEVEL!r}) — "
          f"batch_size={LLM_BATCH_SIZE}, {VERIFIER_BATCH_WORKERS} batches in parallel, "
          f"round-robin across {len(OLLAMA_HOSTS)} GPU host(s) …")

    v_batches = []
    for batch_start in range(0, len(verify_idx), LLM_BATCH_SIZE):
        batch_rows_idx = verify_idx[batch_start: batch_start + LLM_BATCH_SIZE]
        v_batches.append((batch_rows_idx, work_df.loc[batch_rows_idx]))

    t0 = time.time()
    done_batches = 0
    with concurrent.futures.ThreadPoolExecutor(max_workers=VERIFIER_BATCH_WORKERS) as ex:
        futs = {ex.submit(_process_verifier_batch, b_idx, b_df): b_idx for b_idx, b_df in v_batches}
        for fut in concurrent.futures.as_completed(futs):
            result_map = fut.result()
            for ridx, out in result_map.items():
                if out is None:
                    work_df.at[ridx, "verifier_note"] = "verifier unavailable — original verdict kept"
                    continue
                work_df.at[ridx, "verified"]          = bool(out.get("verified", False))
                work_df.at[ridx, "verifier_ambiguous"] = bool(out.get("ambiguous", False))
                work_df.at[ridx, "verifier_note"]      = str(out.get("note", ""))[:150]
                work_df.at[ridx, "verifier_model"]      = VERIFIER_MODEL
            done_batches += 1
            if done_batches % 10 == 0 or done_batches == len(v_batches):
                elapsed = time.time() - t0
                eta = (elapsed / done_batches) * (len(v_batches) - done_batches)
                print(f"  … {done_batches}/{len(v_batches)} verifier batches done "
                      f"({elapsed:.0f}s elapsed, ~{eta:.0f}s left)")

    n_disputed = int((work_df["verified"] == False).sum())
    print(f"  Verifier result: {n_disputed:,} assignment(s) disputed / flagged ambiguous")
else:
    print("Stage 4 — verifier disabled (RUN_VERIFIER_STAGE=False)")
